# 📚 TechHub Documentation: เอกสารระบบและการทำงาน

เอกสารนี้จะอธิบายถึงรายละเอียดของโครงสร้างโฟลเดอร์, ฟังก์ชันการทำงานของ API, และ Utility Scripts ต่างๆ ที่ถูกสร้างขึ้นมาเพื่อช่วยจัดการระบบ E-Commerce "TechHub" 

---

## 1. 🏗 โครงสร้างระบบ (Architecture Overview)

โปรเจกต์นี้ใช้ **React (Vite)** เป็นหน้าบ้าน (Frontend) โดยสื่อสารกับ RESTful API ซึ่งปัจจุบันตั้งค่าให้ทำงานร่วมกับ **JSON Server** ผ่านพอร์ต `3001` (ไฟล์ Database คือ `src/db/db.json`) 
และมีโครงสร้างโฟลเดอร์เบื้องต้นดังนี้:

- `src/` : โค้ดส่วน Frontend ทั้งหมด รวมไปถึง Components, Pages, State management (Zustand) และ Services (Axios)
- `src/services/api.js` : ไฟล์ควบคุมเส้นทางการเรียก API (Endpoints) ทั้งหมดของระบบ
- `src/db/db.json` : ไฟล์ฐานข้อมูลหลักของเนื้อหา (Products, Categories, Users, ฯลฯ)
- `backend/` และ `backend_php/` : ส่วนโครงสร้างและการทดลอง Backend ด้วย PHP/MySQL สำรอง กรณีไม่ใช้ JSON Server
- `public/images/` : ที่จัดเก็บไฟล์สื่อและระบบรูปภาพสินค้าต่างๆ ในระบบ

---

## 2. 🔌 ฟังก์ชันการทำงานของ API (API Services)

ไฟล์ศูนย์กลางที่เชื่อมต่อระหว่าง Frontend และ Backend คือ `src/services/api.js` มีการใช้ **Axios** เป็นตัวส่ง Request. 
ฟังก์ชันหลักๆ ที่เตรียมไว้เพื่อดึงข้อมูลมีดังนี้:

### 📦 Products (สินค้า)
- `getProducts(params)`: ดึงข้อมูลสินค้าทั้งหมด (สามารถส่ง parameters ไปช่วยทำ Filter ยี่ห้อ ราคา สไตล์ได้)
- `getProductBySlug(slug)`: ค้นหาสินค้าจาก Slug (ข้อความลิงก์) สำหรับเปิดหน้ารายละเอียดสินค้า
- `getProductById(id)`: ค้นหาสินค้าเจาะจงราย ID
- `createProduct(data)`: เพิ่มสินค้าใหม่ลงระบบ (สำหรับฝั่ง Admin)
- `updateProduct(id, data)`: อัปเดตข้อมูลสินค้าเดิม (ฝั่ง Admin)
- `deleteProduct(id)`: ลบสินค้าออกตาม ID (ฝั่ง Admin)

### 🏷️ Categories (หมวดหมู่สินค้า)
- `getCategories()`: ดึงรายการหมวดหมู่สินค้าทั้งหมดเพื่อแสดงในเมนู
- `getCategoryBySlug(slug)`: ดึงข้อมูลของหมวดหมู่นั้นๆ 
- `createCategory(data)`, `updateCategory(id, data)`, `deleteCategory(id)`: สำหรับระบบหลังบ้านเพื่อจัดการหมวดหมู่

### 🏢 Brands (แบรนด์สินค้า)
- `getBrands()`: ดึงรายชื่อแบรนด์ทั้งหมดมาแสดง (สำหรับการ Filter หน้าเลือกซื้อสินค้า)

### 👤 Users (ผู้ใช้งานระบบ)
- `getUsers()`: ดึงข้อมูลผู้ใช้งานทั้งหมด (ฝั่ง Admin)
- `getUserByEmail(email)`: ดึงข้อมูลผู้ใช้งานอิงตามอีเมล (มักใช้ตรวจเช็คตอนเข้าสู่ระบบหรือลงทะเบียน)
- `createUser(data)`: สมัครสมาชิกและสร้างผู้ใช้งานใหม่
- `updateUser(id, data)`: แก้ไขโปรไฟล์ผู้ใช้งาน

### 🛒 Orders (ระบบออเดอร์/การสั่งซื้อ)
- `getOrders(params)`: ดึงออเดอร์ทั้งหมดของผู้ใช้งาน (หรือทั้งหมดในระบบ)
- `getOrderById(id)`: ดึงรายละเอียดบิล/ใบเสร็จเฉพาะออเดอร์นั้น
- `createOrder(data)`: ประมวลผลและสร้างคำสั่งซื้อเมื่อทำการ Checkout เรียบร้อย
- `updateOrder(id, data)`: อัปเดตสถานะออเดอร์ (เช่น จาก Pending -> Paid -> Shipped)

### ⭐ Reviews (รีวิวสินค้า)
- `getReviews(params)`: โหลดคอมเม้นต์รีวิวของสินค้า
- `createReview(data)`: สร้างคอมเม้นต์รีวิวใหม่ให้สินค้า

### 🎟️ Promotions (โค้ดส่วนลด)
- `getPromotions()`: ดึงรายการโค้ดส่วนลดในระบบ
- `getPromotionByCode(code)`: ค้นหาและตรวจสอบโค้ดส่วนลด (กรณีผู้ใช้งานกรอกโค้ดลดราคาที่หน้า Checkout)

## 3. 🛠️ Utility Scripts (ฟังก์ชันจัดการฐานข้อมูล / ไฟล์ภาพ)

ในโฟลเดอร์หลักของโปรเจกต์ (`vite-project/`) มีการเตรียมไฟล์สคริปต์ Node.js (เขียนแบบโมดูล `.js`) หลายตัว เพื่อช่วยดูแลรักษาโครงสร้างข้อมูล (`db.json`) ให้สมบูรณ์ ซึ่งทำงานโดยการเข้าถึงไฟล์ระบบปฏิบัติการ (File System - `fs`):

1. **`map_images.js` (สคริปต์ผูกภาพโปรไฟล์สินค้า)**
   - **หน้าที่:** ระบบจะทำการสแกนไฟล์ภาพทั้งหมดในฟลเดอร์ `public/images/products` โดยอ่านตั้งแต่ระดับโฟลเดอร์และการแตกแขนง จากนั้นนำชื่อไฟล์ไปแปลงให้อยู่ในรูปแบบพิมพ์เล็ก แล้วดึงไปเทียบและอัปเดตฟิลด์ `image` และ `images` ในไฟล์ `db.json` หากตรงกันกับชื่อสินค้า (Product Name)
   - **วิธีใช้งาน:** รัน `node map_images.js` ใน Terminal เพื่ออัปเดตพาธรูปภาพอัตโนมัติ

2. **`seed.js` (สคริปต์จำลองและวางรากฐานข้อมูล)**
   - **หน้าที่:** เตรียมและเขียนตารางข้อมูลหลักที่สำคัญลงไปใน `db.json` (และฐานข้อมูลฝั่ง PHP) เช่น สินค้าเบื้องต้น ข้อมูลประเภท หรือข้อมูลทดสอบต่างๆ เป็นเสมือน Dummy data 

3. **`update_images.js`**
   - **หน้าที่:** ควบคุมการปรับแต่งหรือรีมูฟภาพบางส่วน (คล้ายคลึงกับ `map_images.js` แต่เน้นการจัดการที่มีกระบวนการอื่นๆเสริม)

4. **`fix.js` / `clean_db.js` / `restore.js`**
   - **หน้าที่:** ฟังก์ชันสำหรับการทำความสะอาดเนื้อหาขยะ ซ่อมโครงสร้าง JSON ที่ Error และ รีสโตร์ระบบข้อมูลเดิมกลับมาในกรณีที่ทำอะไรผิดพลาด เพื่อรักษาสเตทของ `json-server` ให้ถูกต้องเสมอ

## 4. 🗃️ โครงสร้างฐานข้อมูลหลักใน `db.json`
ไฟล์ `src/db/db.json` ทำงานเปรียบเสมือนฐานข้อมูล NoSQL โดยมีตารางที่สำคัญดังนี้:
- `"products": [...]`
- `"categories": [...]`
- `"brands": [...]`
- `"users": [...]`
- `"carts": [...]`
- `"orders": [...]`
- `"promotions": [...]`

(รูปแบบโดยละเอียดสามารถดูได้จากคุณสมบัติหรือ Property ภายในไฟล์ `src/db/db.json`)

## 📝 บทสรุปและคำแนะนำ

1. **การปรับแต่ง UI:** โค้ดทั้งหมดใช้ TailwindCSS การเขียนหรือแก้ไขสไตล์จะอยู่ใน Component นั้นๆเลยไม่ต้องงมหาไฟล์ CSS แยก
2. **การทำงานร่วมกับ State:** บางที่อาจมีการใช้งาน **Zustand** สำหรับเก็บ Global State เช่น Shopping Cart ข้อมูล Login ของ User ไปจนถึงสินค้าในตะกร้า 
3. **การเข้าโหมด Production:** เมื่อฟีเจอร์นิ่งหมดแล้ว สามารถใช้ `npm run build` ระบบ Vite จะทำการ Minify ทุกอย่างลงโฟลเดอร์ `dist/` เพื่อพร้อมอัปสู่ Server จริง
